Perfeito. Agora descobrimos o motivo.

Veja esta parte:

Capabilities
  completion
  vision
  tools
  thinking

O culpado é exatamente:

thinking

Você não baixou apenas um modelo conversacional.

Você baixou um modelo com capacidade explícita de raciocínio.

Por isso ele faz:

Thinking...
Thinking Process:
...

antes de responder.

O que isso significa?

O modelo tenta:

Interpretar a pergunta.
Planejar uma resposta.
Avaliar ambiguidades.
Só depois responder.

É parecido com a diferença entre:

GPT tradicional

e

Modelos Reasoning

que raciocinam antes de responder.

Para o projeto isso é bom?

Na maioria dos casos:

sim.

Para:

agentes
RAG
planejamento
tomada de decisão
workflows LangGraph

isso costuma melhorar os resultados.

Para conversar no terminal?

Pode ser irritante.

Especialmente quando você quer:

Pergunta
↓
Resposta

e recebe:

Pergunta
↓
Thinking...
↓
Thinking Process...
↓
Resposta









O que eu suspeito que esteja acontecendo

A equipe do Ollama lançou o Qwen 3.5 com:

vision
+
tools
+
thinking

ativados por padrão.

Isso é excelente para:

agentes
MCP
automação
workflows complexos

Mas não é a experiência mais agradável para um chatbot simples.

Minha recomendação para você

Como você está montando um laboratório para:

Ollama
+
Qwen
+
LangChain
+
LangGraph
+
Qdrant

eu manteria exatamente o modelo que você baixou.

Não removeria.

Porque quando você começar a construir:

Supervisor Agent
Planner Agent
Research Agent
Tool Calling

a capacidade de thinking provavelmente será uma vantagem.
